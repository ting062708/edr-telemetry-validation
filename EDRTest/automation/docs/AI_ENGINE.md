## 一、工程目标

**通用目标**：对任意 EDR 产品，验证其对指定「行为清单」的**采集能力**，产出**三态 baseline**（确定采集 / 疑问 / 确定不采集）+ 字段映射 + 行业对比。

**当前实例**：目标产品 = 腾讯 IOA；行为清单见 `SAMPLE_INVENTORY.md`。

- 日志**手动导出**（自动化导出未完成，见行为链②）；
- 样本行为用 **EDR 反哺 + Sysmon 验证**双通道收紧（见行为链①）；
- 产出：三态 verdict + 字段映射 + 行业对比 + AI 行为结果分析。

---

## 二、全局规范（所有行为链都遵循，跨产品通用）

1. **三层 ground truth**：L0 样本声明 → L1 样本 API 回读事实 → L2 独立参照（Sysmon）。判定基准建在「事实」上，**不信样本自述、不信猜测的字段映射**。
2. **三态 verdict**（主结论）：
   - **确定采集** = L2(Sysmon) 确认行为发生 **且** 目标产品日志里出现样本 stdout 的确定值；
   - **确定不采集** = L2 确认行为发生 **但** 目标产品日志里没有该值；
   - **疑问** = 无法下结论（L2 未佐证 / 值有歧义 / 导出窗口未覆盖）。
3. **stdout 补值三原则**：只补「样本确定知道 + 目标产品原样记录」的字符串值；避开枚举状态值（产品中文加工）、系统加工值（UAC、空文件 MD5）、不稳定值（SID）。
4. **锚点**：进程事件用 `Parent.FileMd5`（小写精确）+ `Common.EventTime`（±slack）；内核态/系统进程事件用对象值锚定或 `skip_process_anchor`。
5. **EDR 反哺边界（红线）**：只能反哺「触发方式 / 行为定义」，**禁止**用 EDR 日志字段值定义锚点/期望值（锚点必须来自 L1 样本自报）。
6. **采集延迟差异**：实时钩子类（文件/进程/注册表）毫秒级；异步/轮询/去重类（账户 lsass、建删、服务/计划任务）秒级到几十秒 → slack 设 pre5s/post30s。
7. **留痕**：每个行为做完备份记录；链路每增长一步记录在案；有问题实时追加、不改历史。

## 三、全局优化提示词（7 条，AI 工作准则）

| # | 提示词 | 含义 |
|---|---|---|
| 1 | **版本与编号** | 文档/规则/行为链/样本带版本号（vX.Y.Z）和编号，每次变更递增并留痕 |
| 2 | **自优化上限（默认 3 次）** | 反复交替的自优化行为（如 Sysmon↔EDR 交替验证样本）最多 3 次迭代，3 次未收敛即判「失败/待拍板」，不无限循环 |
| 3 | **结果量化** | 结论必须带数量统计（对/疑问/错计数、覆盖率、命中字段数），不做模糊描述 |
| 4 | **主动求解** | 遇到问题先自行思考并给出解决方法（哪怕不完美），再反馈，不被动等指令 |
| 5 | **问题留痕** | 每个问题写文档记录（编号 + 现象 + 根因 + 状态） |
| 6 | **全局优先** | 操作前先读全局文档，遵循其中规范与提示词建议 |
| 7 | **提示词自优化** | 每轮工作后对现有提示词/规范提 ≥3 条自优化建议，反馈给开发者（元层面迭代） |

## 四、行为链总览（4 个，循环结构）

```
① 样本构建 ──→ ② 跑样本 ──→ ③ 找映射 ──→ ④ 结论分析
     ↑                                        │
     └────────────（反哺：结论发现样本问题）←──┘
```

| 行为链 | 一句话 | 子文件 |
|---|---|---|
| ① 样本构建 | 按行业规范造样本，Sysmon↔EDR 交替验证收紧（3 次失败记样本失败）| `chain/01_sample_build.md` |
| ② 跑样本 | 跑样本→更新 stdout→返回时间段→提示导出日志→手动导出→提交指定区 | `chain/02_run_sample.md` |
| ③ 找映射 | 正向值扫描 + 反向剖析 → 生成 behavior_fields + observed_fields | `chain/03_find_mapping.md` |
| ④ 结论分析 | 三态判定 + 行业对比 + AI 行为结果分析（可反哺①）| `chain/04_conclusion.md` |

## 五、固定输出格式（跨项目复用关键）

每完成一个行为模块，必须产出统一结构（换项目只改内容、不改结构）：

| 产出 | 文件/格式 |
|---|---|
| 三态 baseline | `config/case_result_map.json`：`{case_id: {verdict: 对/疑问/错, note, situations}}` |
| 能力矩阵 | `runs/capability_matrix.csv`：module / case / action / 三态 / 引擎verdict / coverage |
| 字段映射 | `config/mappings/<module>/<case>.json`：behavior_fields + observed_fields |
| 模块结论 | `docs/MODULES.md`（各模块三态结论 + 判定依据）|
