ABOUT · 项目说明

EDR 遥测采集能力自动化验证框架

让冻结协议的行为样本在受控虚拟机中运行，采集 EDR 全量日志，用「数据驱动的字段匹配 + 回归基线」自动判定 EDR 对每一类行为的采集能力——采没采到、采得全不全。

1要解决的问题

传统 EDR 能力验证靠人肉看日志、猜字段，结果是一次性的、不可重复、不可对比、不可信。本项目把它工程化成一套可重复、可对比、可交付的体系。

维度传统做法本项目
字段发现人肉翻日志、逐个猜正反向剖析自动发现
映射生成人肉写映射值扫描自动生成
结果对比跑一次就完，不可比baseline + diff 可回归
可信度靠样本自报三层 ground truth 校验

2核心方法论：用「事实」校验「能力」

验证的基准不能是"样本自报"（声明），必须是"系统实际发生"（事实）。为此定义三层递进的 ground truth：

层含义来源作用
L0 意图样本计划做什么样本 stdout触发 + 锚定
L1 事实样本 API 回读确认的系统状态回读验证主要基准
L2 独立参照第三方采集器客观记录Sysmon 级终极校验
不是信样本自说自话，而是逼近「系统实际发生了什么」。

匹配用「时间窗 + 进程名 + PID + 文件MD5」四要素确定性锚定（主机在导出时已预筛），把样本动作唯一对应到日志事件。

3工作闭环

样本(契约规范)→ 冻结协议 stdout→ 投递运行(VM)→ EDR 采集→ 导出日志→ 字段匹配→ verdict 判定→ 能力矩阵→ 回归基线

4AI 辅助落在哪（四个自动化点）

  • 正向值扫描 — stdout 关键值自动在日志中扫描落点，不再人肉翻日志；
  • 反向剖析 — 枚举日志中有值的字段，反推样本该补什么 stdout 值；
  • 自动生成映射 — 产出 behavior_fields（值锚点）+ observed_fields（采集完整性清单）；
  • 回归检测 — baseline + diff，自动识别采集能力的 🔴回归 / 🟢提升。

6关键认知（沉淀的方法论结论）

  • 判定是两个维度："采没采到"（verdict）＋"采得全不全"（字段映射），不是只看有没有事件；
  • known_gap 不等于 bug：要区分 行业常态缺口（全行业都不采）与 能力缺口（行业能采、本环境采不到）；
  • 内核态事件要换锚点：内核/系统进程事件用对象值锚定（如账户名），不能用进程 MD5 硬锚；
  • 枚举/状态值不可作锚点：EDR 会用中文加工（如"交互式"），只有"样本确定知道 + EDR 原样记录"的字符串值才可信。

7技术架构（分层）

  • 验证层（核心）：字段匹配 → verdict → known_gap
  • 自动化层：批量编排 + 断点续跑 + baseline/diff 回归
  • 展示层：前端（能力矩阵、匹配详情、stdout 高亮、SSE 流）
