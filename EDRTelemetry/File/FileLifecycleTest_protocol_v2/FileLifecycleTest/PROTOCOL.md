# EDR Telemetry Sample Contract - File Manipulation

## Responsibility boundary

- Runner owns TestCaseID selection, fixture preparation, cleanup, and collection timing.
- `FileLifecycleTest.exe` owns only the target file operation.
- One invocation produces one target operation.
- The sample never creates/deletes fixture files as hidden setup/cleanup for another case.
- The sample has no built-in sleep; runner owns pre/post observation windows.

## Invocation

```bat
FileLifecycleTest.exe --case <TestCaseID>
```

## Cases

| TestCaseID | Target behavior | Required precondition |
|---|---|---|
| FILE-CREATE-001 | Create `FileLifecycle_Target.txt` | target absent |
| FILE-OPEN-001 | Open/read `FileLifecycle_Target.txt` | target exists |
| FILE-DELETE-001 | Delete `FileLifecycle_Target.txt` | target exists |
| FILE-MODIFY-001 | Append bytes to `FileLifecycle_Target.txt` | target exists |
| FILE-RENAME-001 | Rename target to `FileLifecycle_Renamed.txt` | source exists, destination absent |

## Exit codes

- `0`: PASS
- `1`: target operation failed
- `2`: invalid/unsupported invocation
- `3`: precondition failed

## Runner rule

Fixture preparation/cleanup should be done by the runner (or a clearly different helper process), not by `FileLifecycleTest.exe`. This keeps telemetry generated by the target process attributable to the requested case.
