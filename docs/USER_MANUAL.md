# EDR 采集验证台 · 使用手册

> 本手册由前端「使用手册」面板实时加载（`GET /api/manual`），修改本文件即更新界面。

---

## 一、这是什么

围绕 EDR 产品做**数据采集能力验证**的控制台：把测试样本投递到 VM 执行，
用样本 stdout 自报与 IOA 云端日志逐字段比对，得出每个行为「采集 / 疑问 / 缺失 / 待测」的判定，
并与行业基线、同学基线对照，支撑 BASELINE 构建与回归测试。

## 二、快速上手

1. 顶栏 **全量投递**：把全部 case 按模块串行投递到 VM 执行（单 VM 串行队列，耗时较长）。
2. 跑完点 **全量匹配**：stdout 自报与 IOA 日志逐字段比对，生成判定。
3. 矩阵「判定」列实时刷新：**绿=采集、琥珀=疑问、红=缺失、灰=待测**。
4. 终端在页面底部，实时显示执行输出；可拖拽上沿调高度，可一键最大化。

## 三、三级操作

| 级别 | 入口 | 说明 |
|---|---|---|
| 单 case | 矩阵行内按钮 / 详情抽屉底部 | 跑样本、匹配 |
| 单模块 | 模块标题带右侧按钮 | 跑本模块、匹配本模块 |
| 全量 | 顶栏按钮 | 全量投递、全量匹配 |

每一级都是「跑（deliver）」和「匹配（match）」两个动作。
匹配默认自动探测最新 IOA 导出日志，也可在详情抽屉「日志」页指定版本。

## 四、判定口径

- **采集（对）**：IOA 完整采到该行为的核心字段。
- **疑问（部分）**：部分情况下有记录——按导师标准「部分=通过」，但保留标记供后续研究。
- **缺失（错）**：完全无采集。
- **待测**：尚无结论（未跑或未匹配）。

判定优先级：case_result_map 定稿 > match 能力结论 > 同学 baseline 兜底（暂时保留）。
手动 case 的结论由人工实测直接写入 case_result_map，与自动化结论同权展示。

## 五、Sysmon（L2）对照

矩阵「SYSMON」列与详情抽屉「Sysmon」页展示每个 case 的 Sysmon 独立参照证据：
Sysmon 采到而 IOA 未采到 → 确认为 EDR 采集盲区；Sysmon 也未采到 → 样本未触发，需改样本。
样本均经人工确认后才会入 case，前端不做自动归因。

## 六、Baseline 对比与总结报告

- **Baseline 对比**（顶栏）：两个视图。
  - **行业基线**：本产品当前判定已并入行业参照矩阵（tsale/EDR-Telemetry，
    Sysmon/MDE/CrowdStrike/SentinelOne），行为列中英对照，逐行为给出「对照」结论——
    `↓ 弱于行业`（行业多数可采而本产品未采到，即补齐优先级清单）、`↑ 强于行业`、`= 一致/均弱`；
    顶部有**模块级差异汇总条**（按弱于行业排序，点击直接筛选该模块矩阵）；
    点「本产品」列徽章可跳到对应 case 详情。
  - **同学基线**：逐 case 对照（演示期兜底参照，暂时保留）。右侧两列可直接填写
    **能力映射名称**（IOA 事件名）与**采集分析**（一两行结论），失焦自动保存，
    与详情抽屉「分析」页互通（存 case_analysis.json）。
- **总结报告**（顶栏）：本轮回归整体结论——覆盖率、较上轮新增/退化、采集强项与关注项，
  支持导出 Markdown。

所有滑出面板（手册/Baseline/报告/详情抽屉）都支持**向左展开**：点面板头右侧的
展开按钮一键整宽（宽表格不用横向拉），或拖面板左缘自由调宽，宽度自动记住。

## 七、映射与采集分析（详情抽屉「分析」页）

每个 case 的详情抽屉有「分析」页，可人工撰写三项内容并保存
（存 `automation/config/case_analysis.json`，随项目走、不占自动化流水线）：

- **能力映射名称**：该行为对应的 IOA 事件名（如 FileWriteClose / ProcessCreate）。
- **映射笔记**：行为 → IOA 事件/字段的人工结论（上方附机器 mapping 的 behavior_fields 只读参考）。
- **采集分析**：采集结论的限制条件、场景边界、与行业的差距原因等。

同学基线 tab 的行内填写与这里互通（合并保存、互不覆盖）。全部内容为空时保存即删除该条。

## 八、变体（多用例确认能力）

一个「能力」可能有多个触发方式（如注册表 Run 键 / RunOnce 键），EDR 采集有偏向性，
需要多个测试样例确认。变体命名约定：`<模块>-<能力>-<序号>`（如 `REG-CREATE-001` / `REG-CREATE-002`）。
前端按 case_id 前缀（去掉末尾序号）自动分组，无需后端改动：

- **矩阵**：同一能力的变体合并为一行「能力行」（蓝色底 + `N 变体` 标签），
  点击或点行首 ▸ 展开各变体子行；能力行操作按钮可整组跑/匹配（串行队列）。
- **能力级并集判定**：全部变体采到 → 采集；部分采到 → 疑问（采集有偏向）；
  全部未采到 → 缺失；含待测且无采集 → 待测。
- **详情抽屉「变体」页**：列出同能力全部变体的判定/投递/匹配状态，点击可切换查看。

## 九、手动能力

USB 插拔、EDR 运维（Agent 启停/安装/卸载/保活/报错）为手动确认能力：
判定徽章直接显示人工实测结论（采集/缺失），右侧跟紫色「手测」小标签，
无自动化按钮、不参与自动化回归；结论与自动化 case 同权计入覆盖率。

## 十、快捷键

- `F1`：打开/关闭本手册
- `Esc`：关闭所有滑出面板

## 十一、数据安全

- 所有状态来自磁盘文件（`results/runs/`、`automation/config/`），刷新页面不丢。
- 回归前建议先打基线：`run_all.py baseline`（快照当前判定到 config/baseline.json）。
